The `none-star` amp model is Greybound's Clean/Edge target for high-headroom
boutique clean tones, round low end, articulate treble, and touch-sensitive
breakup when the input/volume and power response are pushed. The public model
name is intentionally original. Lone Star style references are calibration
targets only, not product identity.

V1 does not attempt to implement a complete two-channel Lone Star platform or
the higher-gain cascading Drive mode.

## Modeling Scope

The current implementation is a tuned graybox approximation. It is not a Mesa
schematic clone, SPICE netlist, or component-exact wave-digital model. The goal
is a useful clean-to-edge target that can later be calibrated against measured
captures, NAM references, or a project-owned SPICE fixture.

Canonical model id:

- `none-star`

Legacy aliases accepted for existing rigs:

- `lonestar-special`
- `lone-star-special`
- `lonestar`

## Source Confidence

Public Mesa/Boogie materials describe multiple related Lone Star-family amps.
The Lone Star Special uses EL84 power tubes, but the larger Lone Star / Lone
Star Classic family uses 6L6 by default, with EL34 compatibility documented in
some materials. The local NAM and the user-provided visual reference are named
and styled as Lone Star rather than Lone Star Special, so the current
`none-star` V1 target is now the larger 6L6 Clean/Edge family, narrowed to the
clean and edge-of-breakup range rather than all modes.

The project has inspected externally hosted schematic PDFs for both the Lone
Star Special and the larger Lone Star classic. Do not commit those PDFs or page
images. Use them only as references for project-owned topology notes. Earlier
V1 notes incorrectly treated the current target as the EL84 Special; that was a
bad fit for the NAM/photo target and has been corrected to a 6L6-style Classic
Clean/Edge target.

## Current DSP Approximation

The first Rust model lives in
`core/src/amp/models/none_star.rs::NoneStar` and uses:

- 1 MOhm-style input coupling,
- a Clean-channel-inspired fixed input triode before the tone stack,
- passive-style bass/mid/treble shaping before the channel gain/recovery stage,
- volume/drive-dependent transition into soft edge breakup after the tone stack,
- recovery/loop-driver shaping into master/presence behavior,
- phase-inverter approximation before the power section,
- 6L6-style higher-headroom push-pull power response for the Classic target,
- slow bias/sag envelope followers,
- output high-pass/low-pass filtering before cab/IR.

`AmpControls::cut` temporarily represents the mid control because the shared
amp control shape does not yet expose a dedicated `mid` field.

## Source-Informed Clean Channel Pass

After re-inspecting the externally hosted Lone Star Special schematic pages,
the old V1 Rust flow was judged too close to the Nox30 family: it effectively
used two gain stages before the tone network, then a generic EL84-like output
curve. The Special clean channel reference instead shows the important musical
ordering as input triode, passive bass/mid/treble network, channel gain/recovery
behavior, master/presence, loop/output driver behavior, phase inverter, and
four-EL84 power section.

The current Rust implementation was changed in that direction:

- first triode is mostly fixed high-headroom input conditioning,
- tone stack happens before the volume/gain push,
- `volume` now pushes the post-tone recovery path rather than the first triode,
- master/presence shaping happens before the phase inverter,
- the power response was initially mapped as an EL84 Special helper, then
  corrected to a `lonestar_classic_6l6_power_bank` helper after reconciling the
  NAM/photo target with Mesa's larger Lone Star / Classic family, which is
  documented as 4x 6L6 by default with EL34 compatibility.

This is still a graybox approximation, not a component-exact schematic port.
The next step, if we want more confidence, is a project-owned SPICE fixture for
the clean-channel tone/gain section rather than another arbitrary voicing pass.

## Lone Star / Classic 6L6 Target Correction

The previous EL84 wording was wrong for the selected NAM/photo target. Mesa's
legacy Lone Star page describes the larger Lone Star as driven by a quartet of
6L6 tubes, and the 1x12 combo specs list `4x Mesa 6L6 (or EL-34)`. The Lone
Star Special is the related EL84 amp, but it is not the best target for the
current None Star archetype.

Code changes:

- rename the power helper to `lonestar_classic_6l6_power_bank`,
- use a higher-headroom 6L6-style current curve,
- keep the source-informed gain-pot bright bypass,
- open the output low-pass from `12 kHz` to `14.5 kHz` to avoid over-darkening
  the cab-fed NAM match after the 6L6 correction.

## Direct Neural 6L6 Power Slot

The implementation now has two power-stage paths:

- a structured analytic `PushPull6L6Stage` fallback with explicit supply,
  screen, fixed-bias, bias-shift, current, load-current, and attack-current
  state,
- an optional direct neural power-stage slot that can replace that fallback
  once a trained artifact exists.

The structured fallback is intentionally a calibration surface, not a claim of
component-complete 6L6 realism. It replaces the previous
`lonestar_classic_6l6_power_bank` waveshaper so future iterations can tune
physical state instead of a one-line transfer curve.

Runtime component id:

- `none-star.power_6l6`

```bash
  --neural-cell-mode replace
```

The current Rust slot expects a scalar-output Greybound MLP artifact with five
features:

1. `power_drive`: phase-inverter/presence-shaped drive into the power section,
2. `bias_shift`: dynamic bias envelope,
3. `sag`: dynamic supply envelope,
4. `edge`: normalized clean-to-edge drive intensity,
5. `sag_control`: normalized user sag/feel control.

The output is the normalized power-stage voltage before output-transformer
filtering. Output transformer filtering, cab/IR choice, and final output gain
remain explicit Greybound stages.

No neural artifact is accepted yet. If no descriptor is provided, or if the
provided artifact does not have five input features, `none-star` keeps the
current structured 6L6 fallback. This keeps desktop/live behavior available
while the lab builds the SPICE-trained artifact.

Interpretation: reducing bias-shift strength, attack-current coupling, supply
sag contribution, and plate-current compression fixed most of the structured
fallback's over-compression. Against the previous open-OT analytic helper it

useful experiment is to recover more mid/presence transient energy without

from a project-owned SPICE fixture.

The direct-neural acceptance path should be:

- build a project-owned `push-pull-6l6` or `none-star-power-6l6` SPICE fixture,
- export train/validation/test traces with the five runtime features or their
  SPICE-equivalent electrical variables,
- train a Greybound MLP artifact,
- run Rust/Python vector equivalence,
- render `shadow` and `replace` full-chain comparisons,
- promote only if the NAM/reference metrics improve without xrun, clip, or
  unstable output behavior.

## Open Assumptions

- Exact channel, revision, and sample settings still need to be chosen for
  long-term calibration.
- Tone stack values and tapers are graybox, not component sourced.
- The 5/15/30 W power switching is represented only as a generic sag/feel
  control in V1.
- Built-in reverb is not part of the amp core; Greybound should keep spring
  effects in FX-loop/runtime effect models.
